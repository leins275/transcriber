# Blueprint: Meeting type as an optional fourth section of the filename

## Summary

A dropped recording is filed by its name, `<PRJ> - <DATE> - <NAME>`, split on the first two hyphens; today anything after the second hyphen — hyphens included — is the title. This feature makes the hyphen a reserved separator everywhere and adds an optional fourth section, the meeting **type**: `<PRJ>-<DATE>-<NAME>[-<TYPE>]`, spaces around separators trimmed, spaces inside a section kept. Three sections parse as before, four carry a type, five or more (a hyphen inside a section) route to `unsorted` — never rejected, exactly like every other non-conforming name. The type persists in the meeting folder name (`<YYMMDD> - <Name> - <TYPE>`), is parsed back from it for display, and is editable from the recording page's existing rename form (which now refuses a hyphen in either field, or the round trip breaks). `crates/vault` stays the single authority; the app and its TypeScript display helpers mirror the grammar; the Python service is untouched.

## Requirements

- **FR-1** (must): `vault::classify_filename` implements `<PRJ>-<DATE>-<NAME>[-<TYPE>].<ext>` with `-` reserved as the separator. The stem is split on **every** hyphen; each section is trimmed of ASCII spaces only (a tab or control character next to a separator still reaches the validators and is rejected, as today).
  - [ ] 3 sections → `Classified::Sorted` with `ParsedName.kind == None`: `ELS - 260812 - Security issue.mp4` and the compact `ELS-260812-Security issue.mp4` both give `ELS` / `260812` / `Security issue`.
  - [ ] 4 sections → `Sorted` with `kind == Some(type)`: `ELS - 260812 - Security issue - Standup.mp4` → kind `Standup`; `ELS-260812-Security issue-Standup.mp4` and `ELS - 260812 - Security issue -Standup.mp4` give the same result; spaces inside sections survive (`GIS - 260724 - Weekly sync - Sprint review.mp4` → title `Weekly sync`, kind `Sprint review`).
  - [ ] 5 or more sections → `Classified::Unsorted { reason: Rejection::TooManySeparators, .. }` with the verbatim stem: `ELS - 260812 - Security - issue - part 2.mp4`, `ELS-260812-follow-up call-Standup.mp4`, `TBOT - 260731 - Запись встречи 31.07.2026 11-04-56 - запись.mp4`.
  - [ ] Fewer than 3 sections → `Rejection::MissingSeparator` (unchanged): `recording_final(1).mp4`, `just one - separator.mp4`.
  - [ ] A present-but-empty fourth section → `Rejection::EmptyType`: `ELS - 260812 - Title - .mp4`, `ELS - 260812 - Title -.mp4`.
  - [ ] The type follows the title's character rules: `ELS - 260812 - Title - Q:A.mp4` → `Rejection::IllegalTypeCharacter(':')`; `ELS - 260812 - Title - CON.mp4` → `Rejection::ReservedDeviceName`.
  - [ ] Check order is: extension gate (`Err(UnsupportedMediaType)`, unchanged, regardless of section count) → section count → project code → date → title → type; first failure wins (`1ELS - 260812 - T - a - b.mp4` → `TooManySeparators`; `1ELS - 260812 - T - K.mp4` → `InvalidProjectCode`; `ELS - 260812 - Q:A - K.mp4` → `IllegalTitleCharacter(':')`).
  - [ ] `ParsedName` gains `pub kind: Option<String>`; `project`, `date`, `title`, `ext`, `stem` keep their meaning. The parser stays pure and panic-free (the existing `tests/parse_fuzz.rs` sweep stays green).
- **FR-2** (must): The error vocabulary names every new outcome. `Rejection` gains exactly four variants — `TooManySeparators`, `EmptyType`, `IllegalTypeCharacter(char)`, `ReservedSeparator` — with distinct `Display` strings that name their subject ("more than three `-` separators … `-` cannot appear inside a section"; "type is empty after trimming"; "type contains the illegal character '…'"; "`-` is reserved as the separator and cannot appear inside the title or type").
  - [ ] `Rejection::all().len() == 13`, all `Display` strings pairwise distinct, `error::exhaustiveness` updated (compile-enforced); `VaultError::all_kinds()` unchanged at 12.
  - [ ] `title::validate_kind(raw) -> Result<ValidTitle, Rejection>` applies `title::validate`'s rules to a type and re-labels `EmptyTitle → EmptyType`, `IllegalTitleCharacter(c) → IllegalTypeCharacter(c)`; `ReservedDeviceName` passes through. `title::validate` itself is unchanged (a hyphen can never reach it from the parser, and `tests/title.rs` pins its current contract).
- **FR-3** (must): The meeting folder name carries the type and can be read back. `paths::meeting_folder_name(date, title, kind: Option<&str>)` builds `<date> - <title>` or `<date> - <title> - <type>`; `paths::parse_meeting_folder_name(name) -> Option<MeetingFolderName { date, title, kind: Option<String> }>` is its inverse: split on every `-`, trim ASCII spaces, 2 sections → untyped, 3 → typed, anything else → `None`; `date` must be six ASCII digits; an empty title or type → `None`.
  - [ ] `meeting_folder_name("260812", "Security issue", None) == "260812 - Security issue"`; with `Some("Standup")` → `"260812 - Security issue - Standup"`.
  - [ ] Round trip: for every valid `(date, title, kind)` (including Cyrillic, `&`, `.`, inner spaces), `parse_meeting_folder_name(&meeting_folder_name(date, title, kind))` returns the same three values; `260812-Security issue-Standup` (compact) parses identically.
  - [ ] Real-vault fixtures: `260828 - Q&A Сессия с Дмитрием - поиск рабочего триггера` → title `Q&A Сессия с Дмитрием`, kind `поиск рабочего триггера`; `260731 - Запись встречи 31.07.2026 11-04-56 - запись` → `None` (five sections); `just a folder`, `26081 - Too short`, `260812 -`, `260812 - Title -` → `None`.
  - [ ] `paths::unsorted_folder_name` is unchanged: an unsorted stem keeps its hyphens verbatim (`260910 - Запись встречи 31.07.2026 11-04-56 - запись`).
  - [ ] Both are re-exported from `lib.rs` (`vault::{parse_meeting_folder_name, MeetingFolderName}`); the crate's `## Naming convention` and `## On-disk layout` docs and `crates/vault/README.md`'s layout block describe the four-section grammar, the reserved hyphen, the 5+ → unsorted rule and `<date> - <Title>[ - <Type>]/`.
- **FR-4** (must): Ingest lands a typed recording in a typed folder. `Vault::ingest` on `ELS - 260812 - Security issue - Standup.mp4` creates exactly `<root>/ELS/260812 - Security issue - Standup/source.mp4`; an untyped name creates `<root>/ELS/260812 - Security issue/source.mp4` as today.
  - [ ] A 5+-section file (`TBOT - 260731 - Запись встречи 31.07.2026 11-04-56 - запись.mp4`) lands at `<root>/unsorted/<ingest YYMMDD> - TBOT - 260731 - Запись встречи 31.07.2026 11-04-56 - запись/source.mp4` with `Classification::Unsorted { reason: TooManySeparators }` — never an error.

  - [ ] Renaming a typed meeting to its own current name is a no-op returning its path; a taken typed destination is suffixed `(2)`; re-filing between projects and to/from `unsorted` carries the type along.

## Architecture

Everything flows from `crates/vault`, which stays the only place that knows the grammar:

1. **Parse** (`crates/vault/src/parse.rs`): `classify_filename` replaces `splitn(3, '-')` with a full `split('-')`, trims ASCII spaces per section, and dispatches on the section count (`<3` → `MissingSeparator`, `3` → untyped, `4` → typed via `title::validate_kind`, `>4` → `TooManySeparators`) before validating code → date → title → type. `ParsedName.kind: Option<String>`. New `Rejection` variants in `error.rs` (plus `all()`, `Display`, the `exhaustiveness` guard); `title::validate_kind` in `title.rs`.
2. **Folder name** (`crates/vault/src/paths.rs`): `meeting_folder_name(date, title, kind)` and its inverse `parse_meeting_folder_name` + `MeetingFolderName`, re-exported in `lib.rs`. `ingest.rs::compute_destination` passes `parsed.kind.as_deref()`; `check_len` already measures the full destination, so FR-5 needs no new code, only tests and docs.
3. **Rename** (`crates/vault/src/manage.rs`): `MeetingUpdate.kind`; `rename_meeting` normalizes blank → `None`, rejects `-` in title/kind (`ReservedSeparator`), validates via `validate_kind`, builds the typed name; `check_move_length` covers FR-5 at rename unchanged. Inline tests' `update()` helper gains `kind: None` (they live in the source file).
4. **App shell** (`apps/desktop/src-tauri/src/commands.rs`, `commands/meetings.rs`): one extra `Option<String>` argument threaded to `MeetingUpdate`. No view change; `view_for`/`meeting_name_of` already report the folder name.
5. **UI** (`apps/desktop/src/`): `lib/fileName.ts` and `lib/meetingName.ts` mirror the grammar (display-only, as their module docs already say); `types.ts`/`api.ts` carry `kind`; `MeetingEditor.tsx` gets the Type field, preview and hyphen guard; `RecordingPage.tsx` and `VaultRow.tsx` render the type from `parseMeetingName`.
6. **Docs**: `lib.rs` module docs + `crates/vault/README.md` (with T3), `CLAUDE.md` (with T5). `docs/setup.md` does not describe the convention — nothing to change.

Data flow after the change: drop `ELS - 260812 - Security issue - Standup.mp4` → `classify_filename` → `Sorted { kind: Some("Standup") }` → `ELS/260812 - Security issue - Standup/source.mp4` → `list_vault` reports `meeting_name` → `parseMeetingName` → title `Security issue`, pill `Standup` → rename form seeds Type `Standup` → `update_vault_entry(.., kind)` → `rename_meeting` → new folder.

**Risks**:

- *Existing tests pin the old grammar* (`tests/parse_filename.rs`, `tests/acceptance.rs::fr02_fr03…`, `tests/error_vocabulary.rs` count, `tests/paths.rs` call signature, `fileName.test.ts`, `meetingName.test.ts`). Each stale file is the **Test first** file of exactly one task, whose test-author rewrites the obsolete cases; until that task's wave, that one file is expected red — the per-task **Done when** is scoped to the task's own test binary, and the final quality gate runs everything. Mitigated by T1–T4, T6, T7.
- *Compile-breaking test literals*: `tests/ingest.rs` and the app's `ingest.rs` build `Classification::Sorted { project, date, title }` exhaustively — mitigated by leaving that enum unchanged (FR-4). `tests/paths.rs` calls `meeting_folder_name` with two arguments — it is T3's own test file, updated first.
- *Round-trip ambiguity on the real vault* (FR-9): accepted by the operator; the six folders are listed here and re-listed in the final report.
- *Payload equality in `RecordingPage.test.tsx`* (`toHaveBeenCalledWith({ project, date, title })`): mitigated by omitting `kind` from the editor's payload when blank (FR-8).
- *Tauri optional argument*: `kind: Option<String>` deserializes a missing key as `None`, and `api.ts` sends an explicit `null` anyway.
